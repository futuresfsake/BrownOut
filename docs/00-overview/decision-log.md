# Decision log

Decisions that are made. Each has the reason and what was turned down. Add new entries at the bottom; do not rewrite old ones. If a decision is reversed, add a new entry that says so.

| ID | Date | Decision | Reason | Turned down |
|---|---|---|---|---|
| DL-01 | 2026-11-15 | The engine is deterministic TypeScript and owns all facts. The model never sets a number, a time, a status or a score. | The product promise is that numbers stay exact and consequences are fair. A model that tracks state in prose drifts over a long session. | Letting the model keep the state in its own context and report it each turn. |
| DL-02 | 2026-11-15 | A turn is three steps: interpret (model), resolve (engine), narrate (model). | Each step can be tested alone. The narrator writes from facts that are already settled, so it cannot influence the outcome. | One model call that both decides and writes. A tool-use loop where the model calls engine functions. |
| DL-03 | 2026-11-15 | Scenarios are authored data files with a hidden ground truth. | A fair mystery needs a fixed answer. Authored clues and red herrings can be tested and balanced. | Scenarios invented by the model at session start (see O-05). |
| DL-04 | 2026-11-15 | Player input is free text. There are no multiple-choice menus. | Deciding what to do without being shown the options is the skill being practised. | Choice buttons. A command grammar. |
| DL-05 | 2026-11-15 | Sim time advances when the player acts, and slowly while idle (one sim minute per 15 real seconds, pausable). | Gives pressure without punishing reading speed. Idle ticks cost no model calls unless a beat fires. | Pure real time. Pure turn-based with no idle pressure. |
| DL-06 | 2026-11-15 | Model: Claude Fable 5.2 (`claude-fable-5-2`) for interpret, narrate and debrief. The model ID is read from configuration. | Long-session consistency of voice and careful reading of messy free text are the two things the model is here for. One model keeps one prompt cache. | A smaller model for the interpret step. Left open as O-03 until measured. |
| DL-07 | 2026-11-15 | All model output is schema-constrained JSON, validated with zod before the engine or the client sees it. | Free-form output cannot be checked. Enumerated IDs mean the model can only pick from what the scenario allows. | Parsing prose with regular expressions. |
| DL-08 | 2026-11-15 | Every beat and every result type has authored fallback text. | A session must finish when the model is slow, declines or fails validation twice. | Showing an error and asking the player to retry. |
| DL-09 | 2026-11-15 | Score is computed by the engine from the event log. The model writes only the debrief narrative and must cite event IDs. | A score the model makes up cannot be defended or tested. | Asking the model to grade the session. |
| DL-10 | 2026-11-15 | No database. Sessions live in memory with a time limit. A finished session can be exported as a JSON event log. | There are no accounts and nothing to keep. Fewer parts to secure and deploy. | SQLite or Postgres for session history. |
| DL-11 | 2026-11-15 | Two run modes: live (calls the model) and replay (plays a recorded session). The public demo runs in replay. | A public page that spends money on every visitor is a liability. Replay also gives repeatable browser tests. | Public live play paid for by the author (see O-01). Asking visitors to paste their own API key into the page. |
| DL-12 | 2026-11-15 | Stack: Node 22, TypeScript, Express 5, zod, React with Vite, Vitest, Playwright. One package, one deployable service. | The engine is a plain module with no framework in it. The author already runs this stack. | Next.js. A separate client and server deployment. |
| DL-13 | 2026-11-15 | A turn's HTTP response is a stream of newline-delimited JSON: intent, then resolved state, then written text. | The board can update the moment the engine resolves, before the prose arrives. | Waiting for the whole turn. WebSockets. |
| DL-14 | 2026-11-15 | Each model request is rebuilt from the engine's event log. Earlier model responses are not replayed as assistant turns. | The engine's log is the single source of truth, the request shape stays simple, and the prefix stays stable for prompt caching. | Keeping a growing chat transcript per stakeholder. |
| DL-15 | 2026-11-15 | Variation between sessions comes from a seed held by the engine, not from sampling settings. | Fable 5.2 does not accept `temperature`, `top_p` or `top_k`. A seed also makes sessions reproducible. | Relying on model randomness. |
| DL-16 | 2026-11-15 | The interface is light by default, built on a duty-logbook identity. See ui-design.md. | A recognisable, deliberate look. Readable in a browser tab next to other work. | A dark "hacker terminal" theme. |
| DL-17 | 2026-11-15 | The project is named BrownOut. | A brownout is a partial failure, which is what most incidents are. | War Room, Sev One. |
| DL-18 | 2026-11-15 | The play screen is a 3D war room, built with three.js through React Three Fiber. Owner's decision. DL-16 still holds for the panels and for flat view. | A room you sit in makes the pressure physical: the phone lights up, the lights sag. It is also a stronger portfolio piece than a page of text. | A flat three-column page as the only interface. |
| DL-19 | 2026-11-15 | The room is for place and attention. Everything read at length or typed is an HTML panel beside the object, never text drawn in the scene. | Text in a 3D scene is blurry, cannot be selected or zoomed, and is invisible to screen readers. Typing into it is unreliable. | Rendering the log and messages on in-scene screens. |
| DL-20 | 2026-11-15 | Room geometry is built in code from simple shapes, in a card-model style with toon shading and inked edges. No downloaded models. | No licence questions, a small download, and a look that belongs to this project. Simple shapes read as a deliberate style when the whole room uses them. | Photoreal assets. Free model packs. |
| DL-21 | 2026-11-15 | The camera moves between five fixed stations. There is no free movement. The decision box and status strip stay on screen at every station. | The game is decisions under time pressure, not navigation. Fixed stations work with a keyboard, on a phone, and with reduced motion. | First-person walking. Orbit controls. |
| DL-22 | 2026-11-15 | A complete flat view is kept alongside the 3D room and is what the automated browser tests drive. | Not every device has WebGL 2 or the power for it, and some players cannot use a 3D scene. Tests against plain HTML are stable. | 3D only. |
| DL-23 | 2026-11-15 | People are not modelled. Stakeholders appear as the devices they contact you through. | Characters are the most expensive thing to make look right and the easiest to make look wrong. A ringing phone carries the pressure. | Animated 3D characters. |
